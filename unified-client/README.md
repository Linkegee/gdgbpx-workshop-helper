# 学院统一客户端 0.1.11（统一50学时目标）

按用户最新约定，本阶段只通过专题获取必修学时，统一目标50，不区分必修/选修。正式已获数继续读首页必修字段；展示分母和非正式统计分母均使用50，不采用网站必修要求25。原始网站要求保留在采集数据中，不改写服务器数据。本次仅改变展示口径，不引入按估算自动停止；以后转为其他学习方式再调整。

## 0.1.10 必修学时口径（目标已由0.1.11覆盖）

正式值和分母从所属账号首页明确的“必修学时：已获/要求”字段读取；不固定50，不使用累计学时替代。专题页每60秒在同一分区发起只读首页请求，解析脱离文档的HTML文本，不执行首页脚本、不跳转播放页；匹配不唯一则保留未知。真实网站登录后格式须重开现场核验，匿名首页没有该个人字段。

非正式统计为正式值加未完成专题中已完成课程标注学时（估算）及明确显示未计入的专题学时。已完成但计入状态不明的专题列为待核验，不重复相加；不能保证网站未提供标记时精确推断计入情况，不参与自动停止。删除首页累计栏，把原门数改名专题课程完成。播放秒数/百分比跟随媒体心跳，服务器百分比保留网站约30秒采样口径，二者不互相代替。

42项单元测试及真实Electron合成测试通过，包含同一首页同时有累计36/50和必修18/25的区分、两个分区分别读取18/25和19/25，以及正式36加专题9得非正式45的计算。已完成但未确认计入的数据仍需要现场证据核验。

## 0.1.9 学习总览

移除面板“重绘画面”按钮，保留0.1.8自动检测、重绘核验及次数限制。顶部“学习总览”显示宽屏账号表：首页采集学时、当前专题已完成/总学时、必修完成数、当前课程和服务器进度、核验时间。支持全部/需处理/未完成筛选，一键进入该账号播放器或专题。进入总览仅隐藏原生页面，页面和独立登录分区继续存在。汇总显示账号数、播放中、需处理、专题完成数及有完整数据账号的专题学时之和，并显示覆盖数。

首页累计学时没有采集到时显示未读取，不用专题学时替代；各账号当前专题学时合计不是单人年度累计。旧专题数据超过两分钟标为待更新。设计参考 [Carbon 数据表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) 的逐行对比与筛选，以及 [PatternFly Dashboard](https://www.patternfly.org/patterns/dashboard/) 的汇总指标布局。验证：真实Electron进入总览、8账号模拟表格截图、移除按钮、切回播放器及自动重绘回归；不对真实账号故意注入故障。

## 0.1.8 自动画面恢复

0.1.8将“全部收纳 / 全部展开”合成一个切换按钮：存在展开账号时收纳全部，否则展开全部，保持各账号播放。主进程自动采样每个页面的低分辨率渲染图像，同时检查选中原生视图的可见性、尺寸和置顶关系。页面加载后保留15秒宽限；前台约10秒检查一次，后台每4秒轮转一个页面。只有间隔至少5秒的连续近全白样本，或选中视图实际隐藏/被覆盖，才触发重绘。白色课件保留播放器边框不会被当成整页白屏，截图失败也不等于白屏。

自动重绘后取两帧非白图像并复查视图关系，验证后才记为恢复。每次故障最多两次重绘、每账号每小时最多三次，未验证恢复进入本地异常监听器，调用真实Codex受限决策并在无法恢复时走现有Bark提醒。媒体或服务器进度仍增长时不会因为显示故障强制刷新；两者均五分钟未增长时才允许对应页面受限重载。人工暂停/停止、关闭异常接管、导航或销毁页面会阻止/取消恢复。

验证包含真实Electron合成播放器隐藏后自动恢复、页面不导航、其他账号不受影响、合并按钮切换；真实Codex合成故障测试验证重绘失败自动升级到通知出口且不重载仍在播放的页面。测试不操作真实账号、不发测试Bark。检测使用页面自己的渲染表面；窗口截图无法包含嵌入原生视图，故不用于判定。操作系统/GPU最终屏幕输出异常仍可能超出这些证据的覆盖范围，不能保证所有白屏和掉线都可无人介入恢复。新主进程和UI需正常退出、重开至0.1.8生效。

## 0.1.7 画面诊断与异常分类

0.1.7根据7882/4335现场证据修正分类：原生stalled事件在readyState>=3且媒体仍播放时记录为info，不作为卡播证据；多个任务scope优先最近的媒体心跳；视频到结尾但服务器未确认时给予两分钟确认窗口，之后标记需要检查，不再反复reload-main。一次恢复未核验后同一故障停止自动重试，直到观察到实际恢复或进入不同课程。通知增加账号尾号/标识和固定原因，避免笼统“异常”被理解为全部账号出问题。

账号摘要区分“任务运行”“媒体播放”“结束待核验”和“心跳过期”。显示切换按Electron文档将选中原生视图置顶，未detach/re-attach；新增“重绘画面”，仅切换显示并请求一帧，不刷新网页、不改变播放位置或学习状态。新增capture-player/repaint-player受限本地命令，把对应播放器截图保存至本机diagnostics，不上传；预加载仅上报DOM数量、可见性和尺寸，不采集网页正文。该措施是显示层加固与取证入口；尚未证明现场整块白屏的唯一根因。

本版测试：29项单元测试，含视频结束误判、重复未恢复重试、旧scope覆盖新媒体；真实Electron合成页面验证反复切换、选中视图置顶、重绘不导航、本地截图非白色目标图面。真实账号不进行破坏性故障注入。监听器可单独更新且不打断客户端；新UI、截图入口及视图层级调整需正常重开0.1.7后验证。参考：[Electron View层级API](https://www.electronjs.org/docs/latest/api/view)。

## 0.1.6 本地异常触发与群控

0.1.6新增“全部开始 / 继续、全部暂停、全部停止”和各账号独立操作。开始错峰发送，正在运行或专题已完成的账号跳过；暂停/停止优先取消尚未发送的开始队列。所有账号先落盘人工保持标志，再向助手发送操作；人工暂停/停止后，恢复命令和重启续播均受保护。界面显示批量返回数及各账号派发结果，派发不等于实际开始播放。

本地 `rescue-worker.cjs` 监听脱敏诊断文件变化（另有十秒本机检查以覆盖文件事件丢失），正常播放不调用模型。已知启动失败、页面进程异常、五分钟媒体与服务器进度均未增长等故障触发一次本机 `codex exec`，使用当前已登录的 CLI、read-only 权限和 JSON Schema 输出。模型只收到账号 UUID、故障分类、阶段、进度数字及课程指纹；不发送姓名、密码、Cookie、Bark key、课程授权、原始日志或网页正文。不得给模型任意客户端执行入口；本地验证决策后只允许匹配的 retry、reload-main、reload-player。主进程再次校验账号、状态、人工保持、60秒命令时效和恢复预算，操作后等待新的媒体或服务器进度，不能凭 CLI/回执成功宣称恢复。

同一账号和阶段十五分钟去重、整个监听器同一时刻最多一个 Codex 调用，每小时最多十二次；主进程每账号五分钟一次、每小时三次的预算独立保留。故障、CLI 缺失/失败/超时、拒绝恢复或恢复未核验时，用现有 Bark 配置提醒；登录/验证码交给用户。UI 可关闭异常接管。CLI 调用会消耗当前 Codex 额度，无额外常驻模型会话。原 automation-4 五分钟 Codex 巡检已删除，由本地事件触发替代。

客户端启动自动启动单实例本地监听器。正常退出会记录用户退出，避免把正常关客户端当成崩溃；整个客户端崩溃时，已独立运行的监听器可告警，但不会盲目重开第二实例。电脑/网络不可用、本地监听器自身退出时不能保证接管或推送。不是无人值守 GUI、自动登录或操作系统级自启动服务。

验证：25项单元测试；真实 Electron 合成页面验证群控暂停/继续/停止、人工保持和停止后的恢复拒绝；`node tests/rescue-engine.cjs` 使用真实已登录 Codex、合成故障与模拟客户端验证自动触发、受限命令回执、后续进度核验，完全不操作真实账号、不发测试 Bark。实际8账号当前播放状态另由本机诊断确认，不用合成测试冒充长期运行证据。`node rescue-worker.cjs --self-check` 可只验证 CLI 连通，无客户端操作。

## 历史版本记录

0.1.1修复两账号同时报“无法读取课程授权”：原适配直接在隔离 preload 中读取网页DOM上的Vue属性，无法跨JavaScript world取得该对象。现在通过contextBridge.executeInMainWorld同步读取有限的课程字段，结果只返回隔离助手；不向网页暴露IPC、不关闭contextIsolation、不修改学院CSP。后台同源进度探测框架单独读取并核对授权，不回退借用主页面授权。真实内核回归先复现原错误，再验证两个账号授权核验和受管播放器启动通过。学院实际播放仍须用户重启客户端后验证。

目标是一个窗口统一管理多个账号。使用 Electron 45.1.0 的持久 Session 分区，每个账号有不同的 `persist:gdgbpx-<UUID>`；由账号页面打开的播放器继承同一 Session。不是向 Edge 注入另一个标签隔离插件，也不读取现有浏览器配置。

## 启动

本机运行 `start.cmd`。依赖已下载。其他机器先执行 `npm ci`，如 npm 禁止安装脚本，再执行 `node node_modules/electron/install.js`。

首次启动预建“账号1”和“账号2”两个分区，分别在学院页面手动登录和输入验证码，用账号备注区分。进入专题后点击现有助手“开始”。不需要再装篡改猴，内置助手为1.5.57。左侧选择账号与播放器；切换不会关闭其他账号页面。关闭页面与退出客户端需要确认。

数据只放在 `%APPDATA%\GanbuUnifiedClient`：账号备注、分区登录状态、助手状态。不会导入或修改 Edge、Chrome、Firefox 的 Cookie。应用不保存账号密码；学院及 Chromium 可保存正常登录 Cookie，请保护本机账户。不要把此数据目录上传到仓库。

“Bark 提醒”配置设备 key；Windows safeStorage 加密保存。若进程已有用户授权复用的 `DAZHONG_BARK_KEY`，首次启动会读取该 key。没有 key 时面板明确显示未配置，不宣称通知已送达。登录/启动异常沿用助手的 Bark 逻辑；进程退出、无响应、加载失败有本地通知及已配置的 Bark 提醒，同类异常五分钟内合并。不能在整个客户端或操作系统已崩溃后自行发送通知。未接入 Codex 自动执行与远程控制。

## 已实现的保护

- 远程网页不启用 Node，启用 contextIsolation、sandbox 和 webSecurity；不修改学院 CSP、证书或认证。
- 助手运行在隔离的 preload world，不向学院网页暴露 IPC / Node。主进程按来源框架、所属账号验证请求。
- 页面跳转与新开页限学院和两个已知播放器 HTTPS 域名。请求站外链接时不会自动放宽权限。
- GM存储在客户端内按真实分区再次隔离，主页面及媒体框架共享所属标签的助手元数据。
- 每个源页面最多一个受管子页面，拒绝重复打开。诊断下载保存到下载目录下“学院诊断”，不反复弹保存对话框。
- 关闭后台定时器节流；任务运行时请求阻止应用因系统空闲挂起。仍可能耗用较多内存，不代表永不冻结或永不掉线。
- 进程无响应/退出时保留账号卡片和错误提示；不盲目重开、重登或伪造学时。重新启动仅恢复账号入口，不恢复旧播放器授权地址。

## 验证和边界

`npm test` 验证分区规则、域名限制和状态摘要。`npm run build` 后，用 Electron 运行 `electron . --self-test`：使用临时数据目录与拦截的合成 HTTPS 页面，不访问真实学院、不加载真实账号。该测试验证真实 Chromium Cookie/localStorage 分离、助手预加载、不同助手 scope、远程页没有 Node/面板桥、子页继承分区、拒绝重复子页及刷新保持存储。

**尚未验证：真实学院双账号登录、验证码、原生跨域播放器、服务器记学时、整课结束切换，以及8账号长时间运行。** 不能将合成测试通过解释为这些业务已通过。未安装签名的独立exe、自动更新客户端、系统外部看门狗；当前通过本目录的启动脚本运行。已有 Edge 播放不会被迁移或关闭。

依据：[Electron Session持久分区](https://www.electronjs.org/docs/latest/api/session)、[安全要求](https://www.electronjs.org/docs/latest/tutorial/security)、[WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)。
