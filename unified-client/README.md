# 学院统一客户端 0.1.4（登录验证版）

0.1.4新增各账号“收纳/展开”、全部收纳/全部展开，默认使用简洁摘要，折叠状态按账号写入本机panel.json并在重启后恢复。折叠只隐藏详情，不隐藏当前课程、服务器进度、异常提示或播放入口，不改变网页、音频或任务。账号卡片和输入框在心跳更新中保持同一DOM节点，避免抢焦点；页面按钮仅在页面列表改变时更新。真实内核测试覆盖独立折叠、批量切换、刷新和落盘、编辑不中断、异常不被折叠藏起、收纳不关视频和不改变静音。

界面借鉴IBM Carbon Accordion与PatternFly Expandable Section的渐进展示原则，采用摘要常驻与详情按需展开，未引入外部UI框架或复制产品代码。参考：[Carbon使用指南](https://www.carbondesignsystem.com/building-blocks/core/components/accordion/guidelines)、[PatternFly设计指南](https://www.patternfly.org/components/expandable-section/design-guidelines/)。

稳定性边界：可以作为持续验证中的主要运行环境，尚不能承诺取代所有Firefox场景或杜绝旧故障。2026-10-29 23:40本机诊断已有8个账号，均有媒体心跳、paused=false、每账号2页；这是单次现场取样，不是长时间8路稳定性测试。网站登录过期、网络/服务器故障、内存压力和进程退出仍可能发生。本机诊断可供Codex在任务中直接读取，但没有部署自动唤醒Codex或无人值守GUI接管，不能保证及时介入或自动恢复所有故障；验证码与重新登录可能需要用户。Bark送达仍需实际验证。保持正在观看的进程，下次正常退出重开才加载新版，不强制中断8账号。

0.1.3补充单实例锁：重复启动只激活已运行窗口，不允许两个进程同时使用一个账号数据目录。更改助手状态保存队列，持续高频心跳不会无限推迟写入；不同账号写入分别处理，失败的脏数据十秒后重试。修复客户端内置助手错误尝试篡改猴更新而生成网络警告，明确显示随客户端更新。未启用远程代码自动安装。

扩展测试：真实Chromium验证第二进程被拒、关闭播放器后原生视图释放及主页面收到关闭回调、另一个账号播放器保留、后台视图尺寸、账号静音分别切换；模拟时钟验证持续心跳仍按时落盘及局部磁盘失败重试。原助手112项回归及构建一致性通过。2026-10-29 23:27—23:31本机0.1.2现场采样确认两账号媒体时间增长且保持静音，账号1服务器进度42.67→58.53；账号2从“大望有望”切换到“脚印——独脚村医三十余载的坚守”，新课服务器进度10%，每账号仍只有主页面+一个播放器。未证明8账号长期并发稳定，未在真实账号上做破坏性故障注入。0.1.3需下次重启客户端后加载，不打断当前观看。

0.1.2修复视频内层框架没有媒体心跳/静音的问题：保留sandbox与Node禁用，由播放器顶层的隔离助手通过同源DOM访问内层视频，读取课程标题、检测问题提示并管理媒体。跨域不可访问的框架不会绕过浏览器隔离。每个WebContents在加载前按所属账号设置音频静音，后续跟随该账号“保持静音”设置；一个账号改变静音不会影响其他账号。后台视图也设置正常尺寸，当前查看的账号启动播放器时自动展示，左侧新增“查看播放画面”。面板只汇总活跃标签的scope，历史停止任务不再堆积显示。

本机自动诊断每两秒合并更新到 `%APPDATA%\GanbuUnifiedClient\diagnostics\latest.json`，包含客户端版本、活跃页面的去查询参数地址、视图尺寸、音频静音、框架列表、对应任务/媒体心跳和最近日志。不包含Cookie、Bark配置、原始课程授权或网页正文，不发送到外部。Codex在本机可直接读取此文件；不是已接通客户端UI控制，也不是持续后台排查服务。旧版也有本地助手存储可读，只有文件不存在、日志缺失或异机时才需要另行提供。

0.1.1修复两账号同时报“无法读取课程授权”：原适配直接在隔离 preload 中读取网页DOM上的Vue属性，无法跨JavaScript world取得该对象。现在通过contextBridge.executeInMainWorld同步读取有限的课程字段，结果只返回隔离助手；不向网页暴露IPC、不关闭contextIsolation、不修改学院CSP。后台同源进度探测框架单独读取并核对授权，不回退借用主页面授权。真实内核回归先复现原错误，再验证两个账号授权核验和受管播放器启动通过。学院实际播放仍须用户重启客户端后验证。

目标是一个窗口统一管理多个账号。使用 Electron 45.1.0 的持久 Session 分区，每个账号有不同的 `persist:gdgbpx-<UUID>`；由账号页面打开的播放器继承同一 Session。不是向 Edge 注入另一个标签隔离插件，也不读取现有浏览器配置。

## 启动

本机运行 `start.cmd`。依赖已下载。其他机器先执行 `npm ci`，如 npm 禁止安装脚本，再执行 `node node_modules/electron/install.js`。

首次启动预建“账号1”和“账号2”两个分区，分别在学院页面手动登录和输入验证码，用账号备注区分。进入专题后点击现有助手“开始”。不需要再装篡改猴，内置助手为1.5.57。左侧选择账号与播放器；切换不会关闭其他账号页面。关闭页面与退出客户端需要确认。

数据只放在 `%APPDATA%\GanbuUnifiedClient`：账号备注、分区登录状态、助手状态。不会导入或修改 Edge、Chrome、Firefox 的 Cookie。应用不保存账号密码；学院及 Chromium 可保存正常登录 Cookie，请保护本机账户。不要把此数据目录上传到仓库。

“Bark 提醒”配置设备 key；Windows safeStorage 加密保存。若进程已有用户授权复用的 `DAZHONG_BARK_KEY`，首次启动会读取该 key。没有 key 时面板明确显示未配置，不宣称通知已送达。登录/启动异常沿用助手的 Bark 逻辑；进程退出、无响应、加载失败有本地通知及已配置的 Bark 提醒，同类异常五分钟内合并。不能在整个客户端或操作系统已崩溃后自行发送通知。未接入 Codex 自动执行与远程控制。

## 已实现的保护

- 远程网页不启用 Node，启用 contextIsolation、sandbox 和 webSecurity；不修改学院 CSP、证书或认证。
- 助手运行在隔离的 preload world，不向学院网页暴露 IPC / Node。主进程按来源框架、所属账号验证请求。
- 页面跳转与新开页限学院和两个已知播放器 HTTPS 域名。请求站外链接时不会自动放宽权限。
- GM存储在客户端内按真实分区再次隔离，主页面及媒体框架共享所属标签的助手元数据。
- 每个源页面最多一个受管子页面，拒绝重复打开。诊断下载保存到下载目录下“学院诊断”，不反复弹保存对话框。
- 关闭后台定时器节流；任务运行时请求阻止应用因系统空闲挂起。仍可能耗用较多内存，不代表永不冻结或永不掉线。
- 进程无响应/退出时保留账号卡片和错误提示；不盲目重开、重登或伪造学时。重新启动仅恢复账号入口，不恢复旧播放器授权地址。

## 验证和边界

`npm test` 验证分区规则、域名限制和状态摘要。`npm run build` 后，用 Electron 运行 `electron . --self-test`：使用临时数据目录与拦截的合成 HTTPS 页面，不访问真实学院、不加载真实账号。该测试验证真实 Chromium Cookie/localStorage 分离、助手预加载、不同助手 scope、远程页没有 Node/面板桥、子页继承分区、拒绝重复子页及刷新保持存储。

**尚未验证：真实学院双账号登录、验证码、原生跨域播放器、服务器记学时、整课结束切换，以及8账号长时间运行。** 不能将合成测试通过解释为这些业务已通过。未安装签名的独立exe、自动更新客户端、系统外部看门狗；当前通过本目录的启动脚本运行。已有 Edge 播放不会被迁移或关闭。
