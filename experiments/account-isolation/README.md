## 已完成

`storage.cjs` 接收一个显式、非敏感的账号作用域标识，为 GM 存储和变更监听添加独立前缀。不同账号隔离状态、事件、心跳、日志和设置；相同账号的主页面与播放器共享该作用域。不自动继承旧的全局运行状态；缺失作用域直接报错，防止误用其他账号状态。销毁时移除本实例监听，禁止继续读写。

`storage.test.cjs` 在两个独立 Node VM 中执行正式脚本的 getState/updateState 路径，共享同一个模拟 GM 后端。基线验证现有版本会互相覆盖；适配器验证两账号同时选择相同课程时，进度、停止和维护状态仍独立。另测同账号播放器通信、不同账号事件隔离、重载持久化、旧状态不迁移和失效作用域处理。

运行：`node --test experiments/account-isolation/storage.test.cjs`

## 看课结束后才能验证的接口

1. MultiLogin 会话 A/B 同时登录后，交替刷新仍显示各自账号。不要把页面显示姓名当作可靠的唯一账号 ID。
2. 手工打开课程产生的跨域验证页、播放器 iframe，是否继承原会话；再次验证 GM_openInTab 打开的标签页。二者不能假设行为相同。
3. 后台同源进度 iframe 是否读取所属账号；GM_xmlhttpRequest 是扩展发出的请求，不能假设经过 MultiLogin 的页面会话隔离。维护探测及恢复必须专门验证，必要时改为会话内探测。
4. 确认可用的作用域传递方式后，主页面、验证跳转、播放器 iframe、刷新和维护恢复必须保持同一作用域。不要猜测 MultiLogin 内部变量名、读取其私有存储或把 token/真实账号写进 URL。
5. 无法确认作用域或播放器会话归属时，应停在等待用户处理状态，不回落到全局状态，不操作任何现有播放器。
6. 两个账号同时运行同名课程，分别暂停、停止、关闭窗口、进入维护和恢复，确认只影响对应账号；再核对各账号服务器记录。

本实验只证明助手存储隔离，不证明网站登录、网络请求、子标签页继承或并发学习成功。作用域解析、播放器传播、多主页面所有权和浏览器集成仍待实现；正式发布前不能省略这些步骤。
